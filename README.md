# Сверка редакций документов

Сервис сравнивает пару DOC / DOCX / PDF: текст, числа, нумерацию, таблицы,
значимое оформление и доступную графику. Сканированные страницы распознаются
Tesseract на русском и английском независимо от переключателя ИИ.
Дополнительная проверка использует только корпоративный `shared-vlm`.
Непроверенные участки показываются отдельно; результат не заменяет юридическую экспертизу.

**Структура:** `app/domain` — модели и алгоритмы; `app/application` — сценарии и
порты; `app/infrastructure` — PDF/OCR/LibreOffice, SQLite, RabbitMQ, VLM и экспорт;
`app/web` — API, шаблоны и модули интерфейса; `tests` — проверки;
`docs` — архитектура и эксплуатационные ограничения.

**Настройки:** Pydantic последовательно читает `.env.example`, `.env`, затем
окружение процесса. Обычные параметры и лимиты находятся в `.env.example`.
Создайте `.env` и запишите только пароль выделенного пользователя RabbitMQ:

```dotenv
RABBITMQ_PASSWORD=ваш_пароль
```

Для нового пароля подойдёт случайная строка, например результат `openssl rand -hex 32`.

При запуске скрипт проверяет существующий `shared-rabbitmq-1`, создаёт отсутствующие
пользователя и vhost `contract-diff`, проверяет пароль и права только на этот vhost.
Повторный запуск сохраняет пользователя и пароль. Несовпадение пароля останавливает
запуск с понятной ошибкой; чужие учётные записи и права не меняются.
Имена задаются в `.env.example` (`RABBITMQ_CONTAINER`, `RABBITMQ_USER`, `RABBITMQ_VHOST`).
Скрипту нужен доступ к Docker этого же хоста; отдельный RabbitMQ не запускается.
VLM не требует API-key. `.env`, `examples/`, `.data/`, `.cache/`
исключены из Git; реальные договоры нельзя добавлять в публичный репозиторий.

**Запуск на Linux** при уже работающем shared-infrastructure и сети `ai-shared`:

```bash
bash scripts/up.sh
```

Интерфейс по умолчанию: `http://localhost:8080`, OpenAPI: `/docs`, готовность: `/readyz`.
Сервис публикуется на loopback. Для корпоративной сети используйте существующий
HTTPS reverse proxy, `COOKIE_SECURE=true` и настройки доверенных proxy-заголовков.
Оригиналы и результаты удаляются через час после завершения; API применяет TTL
при каждом обращении. Отдельные копии PDF имеют серую подсветку замен и зелёную
индикацию добавлений. Word доступен только после проверки содержания и вёрстки.

**Проверки одной командой:**

```powershell
uv sync --frozen
.\ops\check-quality.ps1
.\ops\test.ps1
# Локально, с конфиденциальными examples и эталонной матрицей:
.\ops\test.ps1 -RealDocuments
```

```bash
bash scripts/check-quality.sh  # Ruff и архитектурные правила; нужен uv
bash scripts/test.sh           # Linux-тесты в Docker с OCR, LibreOffice и браузером
```

Успешные подробные логи сохраняются в `.cache/*.log`. Локальные тесты Windows
используют установленные LibreOffice/Tesseract; без них соответствующие проверки
пропускаются. Для локального HTTP: `uv run --frozen python -m app`.
Celery-worker запускается отдельно и требует общий RabbitMQ; поддерживаемый
production-путь worker — Linux-контейнер.
