# Проверка сервиса

Windows: `uv sync --frozen`, затем `./ops/check-quality.ps1` и `./ops/test.ps1`.
Linux с Docker: `bash scripts/test.sh`; сборка и тесты видны в терминале.
Ruff/format/архитектура на Linux: `bash scripts/check-quality.sh`.
Проверки не создают коммиты и не выполняют push.
Для явного сохранения подробностей передайте `--log`: файлы
`.cache/tests-linux.log` и `.cache/quality-linux.log`. Windows-проверки продолжают
сохранять подробные логи в `.cache/`.

На Windows нужны Python 3.12+, uv и Node.js; для полного прогона — Git Bash,
Chrome/Chromium, LibreOffice и Tesseract с языками rus+eng.
Если политика PowerShell блокирует локальные сценарии, используйте
`powershell -NoProfile -ExecutionPolicy Bypass -File .\ops\check-quality.ps1`
и аналогично `-File .\ops\test.ps1 -RealDocuments`; системная политика не меняется.

Наборы: unit (алгоритмы, нормализация), regression (проценты, отрицания, вставки,
перемещения, отказ второго OCR), functional (HTTP→use-case→SQLite→доступ/TTL),
security (архивы, внешние ресурсы, парольные PDF, квоты), architecture (импорты,
документация, Settings, frontend), integration (реальные PDF/OCR/LibreOffice,
девять пар форматов, CropBox/Rotate, 300 страниц, экспорт), browser (Playwright),
frontend (чистые JS-правила через Node test).

Подготовка RabbitMQ проверяется функциональными тестами через настоящий Bash и
временную подмену команды Docker: первый и повторный запуск, исправление прав,
неверный пароль, ошибки CLI/сети/контейнера, административная или чужая учётная
запись. Проверяется точная передача спецсимволов через stdin и отсутствие секрета
в аргументах и выводе, включая запуск с `bash -x`. Это проверка сценария запуска;
она не заменяет подключение к настоящему корпоративному брокеру.
Подмена подключается как функция через `BASH_ENV`: Bash и Python читают временные
файлы без их прямого исполнения. Это работает с Docker tmpfs `/tmp`, где действует
`noexec`. Изменять параметры монтирования или устанавливать Docker CLI в test-образ
для этих проверок не требуется. Каждый сценарий проверяет журнал вызовов подмены,
чтобы ранний отказ фикстуры не выдавался за проверку ожидаемой ошибки.
Проверяются также блокировка параллельного запуска, видимость вывода по умолчанию,
явный `--log`, сохранение кода ошибки и ограничение зависшего клиента.

Настоящий RabbitMQ 4.1 проверяется отдельно:

```bash
uv run --frozen pytest -q -m external tests/integration/test_broker_bootstrap.py
```

Нужны доступный Docker daemon и локальный образ `rabbitmq:4.1-management`.
Тест создаёт одноразовый контейнер без портов и сети, затем удаляет его. Проверяются
создание пользователя с точным паролем, повторный запуск, отказ неверного пароля
и удаление временного файла секрета. Compose и проверка shared-сети подменяются;
команды RabbitMQ выполняются настоящим CLI. Общий production-брокер этим тестом
не изменяется и его доступность не подтверждается.

Windows-скрипт декодирует вывод Node как UTF-8 и использует TAP-отчёт. Поэтому
русские названия тестов и итоговые счётчики корректно читаются в PowerShell 5.

В CI и контейнере используются только синтетические обезличенные документы,
создаваемые `tests/factories.py`. Отсутствие инструментов на Windows отмечается
как skip, а не как прошедшая интеграция. Browser-тесты используют отдельный профиль
Chrome/Chromium и локальную ограниченную тестовую доставку вместо RabbitMQ;
подключение production-брокера этим не подтверждается.

Реальные оригиналы находятся в игнорируемом `examples/`. Эталонная матрица
`examples/golden-matrix.json` ведётся независимо от тестируемого алгоритма.
Нельзя исправлять ожидаемые значения по ответу алгоритма. Коррекция допустима
только после повторной проверки оригинала и записи основания. В частности,
автоматическая нумерация проверяется по Word-рендеру, а не только по `w:t`.
Матрица обязана явно сообщать, когда проверка не исчерпывающая.

Для реальных данных сохраняйте SHA256 исходников, версии инструментов, фактическое
время прогона, найденные значения и области обеих сторон. Сверяйте каждую запись,
отрицательные контроли, false positive, false negative и unverified отдельно.
Один общий similarity score или количество различий не являются приёмкой.

Ручная проверка:

1. Открыть `http://192.168.55.3:8082`, загрузить DOCX слева и скан PDF справа, оставить ИИ выключенным.
2. Увидеть настоящие этапы обработки и два изображения документов.
3. Проверить п. 2.2: 70% → 50%, п. 5.2: предел 5% → 0,01%; дневная ставка не меняется.
4. В п. 4.3.1 цифра 70% одинакова; словесное значение может отличаться.
5. Проверить адрес, счёт поставщика, две печати/подписи и все непроверенные области.
6. Выбрать отличие: обе панели должны перейти к соответствующим местам.
7. Проверить фильтры, поиск, страницы, масштаб, поворот и переключатель связи.
8. Скачать оба PDF, открыть и сверить серую подсветку с реальным изменением.
9. Скачать Word, если доступен; иначе прочитать причину отключения.
10. Проверить сброс/отмену, удаление и недоступность результата после TTL.
11. Повторить с ИИ; при отказе VLM основной результат и PDF должны сохраниться.
