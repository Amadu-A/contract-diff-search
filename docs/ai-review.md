# Два режима ИИ-проверки

Алгоритмический конвейер выполняется всегда. `ai_full` включает полный план:
структурные опоры разделов, все сопоставленные блоки, несопоставленные блоки с
кандидатами во всём втором документе, перекрывающиеся полосы каждой страницы
обеих редакций и графику. Весь текст делится на части без отбрасывания хвоста.
Полосы расширяются до целых пересекающихся абзацев; соответствующие участки
второй редакции объединяются по их фактическим страницам.
Даже одинаковые части имеют разные номера сегментов. Номера страниц не используются
как доказательство соответствия: кандидаты определяются по разделам, словам,
колонкам и структурным опорам. Пропущенные алгоритмами визуальные области
попадают в полный постраничный план.

`ai_unverified` отдельно планирует все оставшиеся корневые неопределённости:
сначала OCR, затем геометрию/соответствие, таблицы, графику, числа и текст.
Если включены оба режима, адресный план строится после полного и учитывает
снятые им неопределённости. Не требуется повторять уже проверенные области.
Непроверенные участки сохраняются при недостатке доказательств — принудительное
обнуление счётчика запрещено.

`VLM_BATCH_SIZE=12` ограничивает число ожидающих операций одного пакета, а не
объём документа. После первого пакета идут второй, третий и остальные.
`VLM_CONCURRENCY=1` ограничивает одновременно выполняемые запросы; допустимый максимум — 3.
`VLM_RETRIES=2` ограничивает повторы временных HTTP/сетевых ошибок, пустого/обрезанного
ответа и ошибок JSON. После 429/503 применяется ограниченная экспоненциальная задержка.
Успехи соседних операций сохраняются независимо от отказа одной из них.

`VLM_CONTEXT_CHARS=3600` ограничивает текст каждой стороны одной операции;
`VLM_IMAGE_PIXELS=2000000` — размер контактного листа каждой стороны.
В запросе не более двух изображений с подписанными исходными областями.
`VLM_REGIONS_PER_REQUEST=6` ограничивает количество кропов каждого контактного
листа: большие наборы делятся на следующие операции без потери областей.
`VLM_TIMEOUT_SECONDS=90` ограничивает отдельный запрос,
`VLM_TOTAL_SECONDS=2400` — проходы ИИ одного запуска, а `JOB_TIMEOUT_SECONDS=3600`
— всё задание. При достижении бюджета хвост явно помечается невыполненным;
повтор продолжает его с новым бюджетом. Это не полная проверка документа.
`VLM_MAX_FRAGMENTS` принимается только для совместимости и больше не ограничивает план.

## Доказательства и объединение

Промпты версии 1 находятся в `app/infrastructure/prompts.py`: отдельные инструкции
двух режимов, страницы, текста, OCR, соответствия, таблицы, графики, чисел и
технической полноты. Документы трактуются как недоверенные данные.
Готовая матрица алгоритмических различий модели не передаётся.
Полнота плана и завершённых операций дополнительно проверяется приложением.

Модель возвращает только разрешённые `oN`/`nN` ссылки, точные значения, цитаты,
основание и уверенность. Координаты из ответа не принимаются.
Подтверждение требует однозначной привязки цитат к независимо извлечённым словам
с проверенной геометрией и достаточной уверенностью.
Пара также должна иметь независимое структурное соответствие; несовпадение
колонок покупателя/поставщика не становится подтверждённым изменением.
Для адресного режима дополнительно перечитываются исходные кропы OCR. Полное совпадение обоих проверенных
кропов и визуальное согласие модели могут снять ложное OCR-расхождение.
Частичная цитата не снимает предупреждение всего абзаца. Нечитаемая печать,
низкая уверенность OCR, неоднозначный ref или отсутствие геометрии остаются явными.
Для чистого числа точное локальное повторное OCR с достаточной уверенностью
может подтвердить первичное чтение, даже если общий анализ строк его не сопоставил.
Итоговая уверенность — минимум двух измерений, без предварительного искусственного
снижения. Знаки и десятичные разделители сохраняются; для смешанных идентификаторов
дополнительно требуется независимое согласие букв. Значения другой редакции
не используются для исправления OCR.
Перед ИИ готовый Word-рендер дополнительно проверяется на уникальные точные
цитаты для отсутствующей геометрии. Координаты берутся из нативных слов PDF;
повторяющиеся цитаты не угадываются. Сами статусы от такого уточнения не меняются.

Подтверждённые алгоритмические факты не удаляются. Противоречие с ответом ИИ
сохраняется отдельным замечанием. Новое AI-замечание имеет `needs_review`, пока
не появятся независимые доказательства. Повтор не дублирует уже найденный факт.
Сохраняются источник, режим, способ проверки и исходная история неопределённости.
`total` считает подтверждённые различия; `ai_needs_review` и уникальные корневые
неопределённости считаются отдельно. Общие предупреждения не распространяются
с одной проблемной страницы на весь документ.

## Прогресс, повтор и экспорт

После алгоритмов сохраняется базовый результат. Каждая операция ИИ получает
стабильный ID и атомарный checkpoint с результатом, цитатами и локальными
доказательствами. API состояния отдаёт только технические счётчики.
`GET /api/v1/comparisons/{id}/ai/operations` показывает владельцу журнал с пагинацией.
`POST /api/v1/comparisons/{id}/ai/retry` повторяет незавершённые операции,
не запуская заново OCR, LibreOffice и алгоритмическое сравнение.
Ограничения доступа, CSRF, TTL и квоты действуют и при повторе.

У каждого режима собственные `planned`, `processed`, `succeeded`, `failed`,
`remaining`, обработанные страницы и категории ошибок. Успешный технический
ответ не равен доказанной идентичности содержимого. Если отдельная область
не прочитана полностью, операция и режим не получают ложного полного завершения.
Страница считается обработанной только после успеха всех её запланированных операций.

`show_unverified=false` — исключительно настройка представления. Она убирает
непроверенные области из списка, деталей/навигации, обеих подсветок и экспорта.
Исходные статусы, покрытие и счётчики не меняются. Подтверждённый факт остаётся
видимым, даже если имеет общий якорь с предупреждением.
По завершении заранее формируются два PDF и, когда безопасно, два Word-варианта.
Переключение не вызывает OCR и не использует артефакт с другим параметром.
Во время изменения результата ИИ старый экспорт недоступен до подготовки актуального.
PDF различает серые/зелёные факты, оранжевые непроверенные области и фиолетовые
ИИ-пометки. Неподтверждённые ИИ-области имеют пунктирный контур без заливки; лёгкая заливка
добавляется только подтверждённым ИИ-различиям.
Word выдаётся только после проверки текста и повторного рендера; при отсутствии
безопасной логической привязки показывается причина недоступности.

## Подтверждённая причина прежнего отказа

27.10.2026 на реальном фрагменте корпоративный endpoint вернул HTTP 200,
`finish_reason=length`, `completion_tokens=700`, `content=null`: лимит ушёл в
рассуждения. Прежний код скрывал причину общим сообщением о недоступности ИИ.
Тот же запрос с `enable_thinking=false` и лимитом 3072 вернул корректный JSON
за 0,313 секунды. Поддержка JSON Schema отдельно подтверждена реальным запросом.

Новый адаптер по умолчанию использует `VLM_DISABLE_THINKING=true`,
`VLM_MAX_TOKENS=3072`, `VLM_MAX_RETRY_TOKENS=6144`, `VLM_JSON_SCHEMA=true`.
Структурированный ответ соответствует [официальному контракту vLLM](https://docs.vllm.ai/en/latest/features/structured_outputs/).
При явно неподдерживаемой схеме допускается ограниченный повтор в JSON-режиме;
Pydantic-валидация остаётся обязательной. Неподдерживаемые флаги не возвращаются
в последующих попытках одной операции. Модель, параметры GPU и общий брокер не меняются.

JSON-события `ai_response_received`, `ai_unit_failed`, `ai_json_validation_failed`,
`ai_unit_checkpoint`, `ai_pipeline_failed` содержат технические ID, режим,
пакет/попытку, длительность, HTTP, причину завершения, статус JSON и категорию
ошибки. Они не содержат тексты, изображения, base64, ответы модели или credentials.
Celery сохраняет JSON-формат приложения и уровень INFO.

OpenBLAS/OpenMP/MKL/NumExpr/BLIS/VecLib ограничены до первого импорта нативных
библиотек через Docker ENV, Compose и Pydantic Settings. `NATIVE_THREADS=1` —
верхняя граница. Healthcheck `python -m app.worker_health` не импортирует OCR/PDF/NumPy
и требует pong только от worker текущего контейнера. `pids_limit` не увеличивается.
